# M8 — Failure injection

**Milestone:** M8 · **Decision:** ADR-0013 · **Scripts:** `scripts/m8_failure_injection.sh`, `scripts/m8_evidence.py` · **Steps:** `app/src/androidTest/kotlin/app/proxyflow/e2e/KillSwitchEndToEndTest.kt` · **Lab:** `scripts/e2e_env.sh` (the witness, port 8095)

M8 asks for tests of tunnel failure, proxy disconnect, network changes, permission revocation and process death, and that an engine failure never silently sends supported traffic directly. This page lists where each failure is injected and checked, and gives the device results of the one M8 adds: the process ending while connected, with and without Android's kill switch, and a crash with a planted secret.

## 2. How the process-death scenarios run

After the device tests and their logcat, `scripts/e2e_device.sh` runs `scripts/m8_failure_injection.sh`, which installs the app and its test APK again and drives `KillSwitchEndToEndTest` one step at a time (`am instrument -e m8 <step>`), doing from outside what no test inside the app's process can: killing it, crashing it, and having Android's Always-on VPN start it.

- **The witness.** A destination on the runner's loopback (`127.0.0.1:8095`). The phone reaches it directly as `10.0.2.2:8095`, but never through a proxy (Dante would connect to 10.0.2.2, where nothing listens; Squid refuses the port, which is not one of its `tunnel_ports`), so every line it logs got out around ProxyFlow. The lab checks this from the runner before the emulator starts (`scripts/e2e_lab_check.py`). It covers one kind of traffic: the shell's TCP to one IPv4 address. What else apps send meanwhile — UDP, DNS, IPv6 — is not probed; the captures report what reached ProxyFlow's own addresses (below).
- **Killing.** `kill -9` of the app's process as the app's own user (`run-as`), as Android's low-memory killer ends a process; where that fails (on the Android 10 image `run-as … kill` answers "unknown pid"), as root (`su 0`, which the emulator images have), and only then a force-stop. The script checks the process is gone.
- **Android's kill switch.** The test APK holds a device admin used only in the lab (`LabDeviceAdmin`), made device owner with `dpm set-device-owner`; its command receiver (`LabAdminCommands`, behind DUMP, which only the shell has) calls `DevicePolicyManager.setAlwaysOnVpnPackage(ProxyFlow, lockdown = true)` — the setting Android's VPN settings make when the user turns on Always-on VPN and "Block connections without VPN", reached another way: turning it off through the device owner withdrew ProxyFlow's VPN consent on Android 14 and 16, so the script gives it back — and afterwards turns it off and gives up device ownership.
- **Nothing else is touched while ProxyFlow is down.** No lab name is looked up and no lab destination contacted while ProxyFlow is not connected, so the M5 and M6 evidence, which check the whole run's DNS and captures, are unaffected.
- **Nothing is left behind.** Whatever way the script ends — a failed step, an early return, its time limit (10 minutes, with 8 more for the step it waits on and the clean-up before it is killed; it is not run when the device tests ran out of time) — no step is left running, Always-on VPN is turned off, the device owner given up and ProxyFlow's VPN consent given back, and the steps it took are printed; a second stop while it cleans up or prints is ignored, so neither is cut short. A step is told the phone's time before its scenario connected (`-e since`), so an interruption an earlier scenario left is never taken for its own (a scenario whose time can't be read does not run); an unknown expected reason fails the step. The next start's step reads the stored interruption afresh while it waits for it.

**A — killed while connected, no Always-on VPN.** The step connects the chosen profile, shows a line reaching the destination through the proxy, and waits; the script kills the process (and checks Android lists it no more — an adb failure is not taken for that), then probes the witness from the shell every half second (at most 20 times) until it answers — the negative control: it shows what Android does without its kill switch, and that the witness and the captures would see a leak. The next start (step `afterProcessDeath`) must begin Disconnected with no notification left, have found the interruption of that connection with the reason Android gives (Android 11+: killed, other or low memory; Android 10: unknown), the profile, the end time (Android 11+) and the log entry, and — having found it — still be Disconnected with no VPN interface.

**B — Always-on VPN with "Block connections without VPN".** The device owner sets it; Android starts ProxyFlow, which connects the chosen profile and reads that blocking is on; a line goes to the destination through the proxy; the process is killed. Once Android lists no VPN network (so a probe can't go into a VPN that is still there), the witness is probed up to 40 times: every probe must be refused as Android's blocking refuses a connect (`EACCES`, "Permission denied"; an answer from the witness fails at once, and anything else — a timeout, a refusal by a proxy, adb gone — fails too), until Android starts ProxyFlow again if it does (its "always-on start" in the log ends the probes: one then goes to the new VPN; the log is looked at once more before the next step). The witness must log none of them, and no capture that sees the uplink through B may hold a SYN to it while the setting is on. The next start (step `afterLockdownKill`) must have kept what Android said (on, blocking), found the interruption (force-stopped instead when Android had started ProxyFlow again: `am instrument` stops that one), find Android still blocking — the shell's line to the witness refused before ProxyFlow connects (Android lets ProxyFlow's own connections through, the shell's not) — and connect again while Android blocks everything else (a line reaches the destination through the proxy). Then the setting is turned off, ProxyFlow force-stopped, and the witness must answer the shell directly again (the second negative control).

**C — a crash with a planted secret.** The step connects, then throws `IllegalStateException("PF8-planted-<token> proxy pf8user:PF8SECRET<token>@planted.pf8.invalid:1080 failed")` on a thread of its own, as a bug's exception would reach the top of a thread. The process must end; Android's crash report (`dumpsys dropbox --print data_app_crash`, looked for for up to 20 s: Android writes it after the process has gone) must name the exception (`PF8-planted-<token>`) and hold none of the planted sign-in — `PF8SECRET<token>`, `pf8user`, `planted.pf8.invalid`; the next start must find a crash (Android 11+). The phone's own log is searched too: Android's runtime writes the uncaught exception there itself before any app code runs — the evidence reports that count; no app can change it (ADR-0013 §7).

`scripts/m8_evidence.py` then checks the steps the script noted (with the phone's time) against the witness's log, the captures of the phone's uplink and the crash report, and fails on any check that doesn't hold or any step the script marked FAILED, timed or not. The witness may hear only what a step sent around ProxyFlow on purpose (the line before the tests, A's probes, the probes once B's setting was off), and nothing at all between A's line and the first once the setting was off. A capture speaks for B only if it holds the SYNs of both A's and B-after's answered lines — B lies between them — on a clock that lines up with the phone's: its offset is measured from those two SYNs, each of which left between two notes the script made, and B's window is placed on the capture's clock within that measure; a capture whose tcpdump had stopped before the end of the tests doesn't count, and at least one must. Its checks have their own tests (`scripts/tests/test_evidence.py`, `M8EvidenceTest`: a run where everything holds passes; a line heard or a SYN seen while blocking, a probe answered or failing any other way than Android's refusal, probes while Android still had a VPN network, a line no step sent, negative controls that never reach the witness, any part of the planted sign-in in the crash report, a failed step with or without a time, a missing step, a process that couldn't be killed, a capture that saw only A's line or stopped early each fail; a capture on another clock is lined up, and a start of ProxyFlow by Android ends the probes).
