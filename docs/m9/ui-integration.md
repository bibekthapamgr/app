# M9 — UI integration and feature completion

**Milestone:** M9 · **Decisions:** ADR-0014 · **Boards:** `design/screens/` (M1) · **Results:** `docs/m9/ui-regression-results.md`

What each screen shows and where it comes from, what each control does, and where that is tested. Nothing on a screen is a sample or a stand-in: every state is the repository's, the VPN session's or the engine's, and the screens never set a connection state themselves (ADR-0010 §2: the session alone writes it).

## 1. Where each screen's data comes from

| Screen (boards) | Shows | Source |
|---|---|---|
| Onboarding (A1–A3) | What ProxyFlow is, what a proxy must be, what goes through it and what is blocked, the VPN permission; the notification permission on Android 13+ | Static text; whether A3 is needed from Android (`POST_NOTIFICATIONS` granted?); finishing writes `onboarding_completed` (DataStore, `SettingsRepository`) |
| Home (B1–B9, H1, H2) | The profile Home connects, the connection's status, stage, error, reconnect attempt, diagnostics and traffic; Android's kill switch as last reported; an interrupted connection | `ProfileRepository` (Room), `VpnRuntime.state` (the session), `VpnRuntime.diagnostics` / `traffic` (the engine's counters, once a second while shown), `ProtectionStore` (M8) |
| Profile picker (B8) | Every profile, the one Home shows chosen, each one's last test | `ProfileRepository.profiles`, `.lastTests` (Room v3) |
| Profiles (C1–C3) | Every profile, the active one, the one a connection uses, each one's last test or the test running | `ProfileRepository`, `ConnectionController.state`, `ConnectionTester.testSaved` |
| Add/Edit proxy (D1–D9, H3) | The form, its errors, whether a saved password is kept, the test's answer | `ProfileRepository.loadForEditing` (Room + Keystore), `ProfileValidator`, `ConnectionTester.test` (the engine) |
| Settings (E1, E1b, E2) | The kill switches, how long logs are kept, whether status notifications are on, the theme | `ProtectionStore` (Android's answers, M8), `SettingsRepository` (DataStore), `NotificationManagerCompat.areNotificationsEnabled()` read each time Settings is shown |
| Logs (F1–F3) | The diagnostic log, how long it is kept | `LogRepository` (Room `logs.db`), its retention from Settings |
| About, privacy policy, help, licences (G1–G4) | Version, limits, the policy, help topics, the libraries shipped and their licences | `BuildConfig`; the app's strings; `open_source_licences.json` and the licence texts (assets, generated by `scripts/licences.py` and checked in CI) |
| Quick Settings tile (B11) | On or off, with what ProxyFlow is doing ("Add a proxy first" without a profile) | `VpnRuntime.state`, `VpnRuntime.shownProfile` |
| Notifications (B10) | The connection's status and problems | `VpnRuntime.state` (M5, M7) |

"Connected" appears only when the session publishes `Connected`, which it does only after the engine runs on the interface and Android routes apps into it (ADR-0010 §3); the tile and the notification read the same state, which takes a rename of the connection's profile at once (`VpnSession.profileRenamed`). A test's "Proxy works" appears only when the engine opened the tunnel (`EngineConnectionTester`, ADR-0014 §1).

## 3. Empty, loading and failure states

| Screen | Empty | Loading | Failure, and the way out |
|---|---|---|---|
| Home | B1, Add proxy | a spinner until the first state | each catalogue code with its fix (B6–B6d, H1, H2) |
| Profiles | C1, Add proxy | a spinner | a snackbar when Use, Duplicate, Delete or Test could not complete (storage, Keystore, engine) |
| Add/Edit | — | the form waits for the profile | "Couldn't open this proxy" with nothing changed; "Couldn't save this proxy. Try again."; H3 when the saved credentials can't be read |
| Settings | — | the rows' current values stay blank until read | "Couldn't clear the logs. Try again." (the log stays as it was) |
| Logs | F1, what will appear and what never will | a spinner | — (an empty filter says so) |
| Licences | — | — | "Couldn't open the licences" (never expected: they are in the APK) |
| Tile | off, "Add a proxy first": a tap opens Home | — | opens Home for anything it can't do itself |

## 4. Not in M9

- The Settings board's "Reconnect automatically" and "Record destinations" switches (ADR-0014 §6).
- A public privacy policy URL and a support contact (owner decision D9, new in M9): `docs/m9/privacy-policy.md` is the text, made from the app's own.
- What "Test connection" contacts (open decision D6): the pre-flight target, one constant.
