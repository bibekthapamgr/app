# M12 — Launch and maintenance: acceptance report

**Status: every M12 acceptance criterion passes — the ones a repository can hold (a changelog and regression results per release, a named owner and a process for critical security reports, profile data compatible across versions or safely migrated, rollback and incident instructions, the policy and dependency reviews scheduled) are in the code, the workflows and the documents, checked by CI on every push, and green in all three attempts of one `android` run and one `release` run of the same commit, after two independent reviews of the work (A, B) and three rounds of re-review of their fixes (RA, RB, C), with every finding fixed or, where the behaviour is a deliberate trade-off, documented. What remains is the owner's by nature — the mailbox's auto-reply, naming the second person, the two drills, the decisions D2 and D10 carried over from M11, and Play Console itself — and is listed at the end.**

## Reviews

Each review is an independent reading of the documents against the code, the workflows and Google Play's published rules, with its own probes (sentences against the redactor, edits against the lock, the runbook's steps tried in the order written, Room's behaviour against the migration tests); each finding is in `docs/m12/defect-register.md` with its fix and the test, document or run that guards it.

| Review | Of | Found |
|---|---|---|
| A | The support and security process, the redactor, the data-behaviour lock, the target API check, the release scripts, dependabot, the maintenance workflow | Fixed (six high: hosts and password forms the redactor let through, a lock every version bump broke, a hotfix version scheme the checker refused; a public issue template for security reports; dependabot's ignore list; the monthly schedule GitHub silences) or documented (a target-API warning that never fails CI) |
| B | The runbooks and the release discipline against the code and Google Play | Fixed (three high: a downgrade migration that Room would not open and `DROP COLUMN` API 29–33 lack, a rollback merge that could not be done, a history row naming a commit the release would not be built from; the known-issue notice with nowhere to go; vitals' terms; the credential format's versioning) |
| RA, RB | A's and B's fixes | Fixed (the notice left up without a warning, the lock's remaining gaps, the checker's two gates in the runbook's order, the redaction that went too far) |
